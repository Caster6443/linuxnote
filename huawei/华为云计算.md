# 基础存储业务配置介绍

- **硬盘域（Disk Domain）**  
    由多块物理硬盘组成，硬盘可选 **SSD、SAS、NL‑SAS** 中的一种或多种。  
    一个存储系统可创建多个硬盘域，不同硬盘域之间实现故障隔离。  
    硬盘域内的空间一部分用作**热备容量**，另一部分用于创建**存储池**。  
    底层的块级虚拟化将硬盘空间切分为固定 **64 MB** 的小块，称为 **CK（Chunk）**。
    
- **存储池（Storage Pool）**  
    由硬盘域中来自不同硬盘的多个 CK 组成。  
    一个硬盘域可创建多个存储池，各存储池可包含一种或多种类型的 CK。  
    同类型的 CK 按照 **RAID 策略** 组合成 **CKG（Chunk Group）**，CKG 的 RAID 策略可根据业务需求选择。  
    在存储池内，CKG 又被进一步划分为 **Extent**。  
    Extent 大小可按需设置，可选值为：512 KB、1 MB、2 MB、**4 MB（默认）**、8 MB、16 MB、32 MB、64 MB。  
    **Extent 是存储池中申请/释放空间、数据统计和数据迁移的基本单位。**
    
- **LUN**  
    在存储池中创建，由多个 Extent 组成，可包含一种或多种类型的 Extent。  
    LUN 的容量可按业务需求动态调整。  
    最终 LUN 被映射给主机，供其进行数据读写。
    
- **主机组（Host Group）**  
    将需要访问相同 LUN 的一台或多台主机（通过 WWN 或 iSCSI 启动器名称识别）加入到同一个组内，用于统一管理存储访问权限。  
    创建映射时以主机组为操作对象，避免逐台配置。
    
- **LUN 组（LUN Group）**  
    将需要映射给同一主机组的一个或多个 LUN 放入一个逻辑集合，方便批量添加/移除映像。  
    一个 LUN 可以属于多个 LUN 组，便于灵活组合。
    
- **映射视图（LUN Mapping）**  
    将某个 **主机组** 与某个 **LUN 组** 建立关联，并指定读写策略（如读写、只读），一次配置即可让主机组内所有主机访问 LUN 组内的所有 LUN。  
    映射视图是存储资源对主机 “可见” 的前提，也是故障切换、多路径管理等的基础。

*   **NFS ( Network File System )** 是Sun Microsystems在1984年创建的Internet标准协议。开发NFS是为了允许在局域网上的系统之间共享文件。
*   **Linux NFS客户端**支持三个版本的NFS协议：NFSv2 [RFC1094]、NFSv3 [RFC1813]和NFSv4 [RFC3530]。其中NFSv2使用UDP协议，数据访问和传输能力有限，已经过时；
    *   NFSv3版本在1995年发布，添加了TCP协议作为传输选项，被广泛使用；
    *   NFSv4版本在2003年发布，已获得更好的性能和安全性。
*   **NFS的工作机制**：主要是采用远程过程调用RPC机制。
    *   RPC提供了一组与机器、操作系统以及低层传送协议无关的存取远程文件的操作，允许远程客户端以与本地文件系统类似的方式，来通过网络进行访问。
    *   NFS客户端向NFS服务器端发起RPC请求，服务器将请求传递给本地文件访问进程，进而读取服务器主机上的本地磁盘文件，返回给客户端。
*   **CIFS ( Common Internet File System )** 是一种网络文件系统协议，用于在网络上的机器之间提供对文件和打印机的共享访问。现在主要实现在Windows主机之间进行网络文件共享功能。
